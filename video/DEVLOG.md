# ReelCut 개발 일지

## 로드맵 (우선순위 순)

**우선순위 기준** (위가 먼저)
1. 작업이 날아가거나 결과물이 잘못 나오는 문제 (데이터 손실·오동작)
2. 사용자가 직접 겪고 알려준 불편
3. 매번 쓰는 흐름(편집 → 미리보기 → 내보내기)의 체감 속도·편의
4. 결과물 완성도를 높이는 새 기능

이 기준으로 아래 순서를 정하고, 위에서부터 차례로 진행.

| 순위 | 항목 | 이유 | 상태 |
|---|---|---|---|
| 1 | 렌더링 병렬화 (조각을 여러 개 동시에 인코딩) | 기준 3: 비트 맞춤은 조각이 수백 개라 느림 (기준 정하기 전에 시작) | ✅ 완료 |
| 2 | 자동 저장 + 다음 실행 때 복구 | 기준 1: 실수로 닫거나 오류로 꺼지면 작업이 날아감 | ⏳ |
| 3 | 취소·오류 처리 다듬기 (렌더 중 취소, 파일이 없어진 경우 등) | 기준 1: 오래 걸리는 작업이라 중간 취소·파일 이동이 잦음 | ⏳ |
| 4 | 진행률에 남은 시간 표시 | 긴 렌더링에서 언제 끝날지 알 수 없음 | ⏳ |
| 5 | 클립 목록 썸네일 | 파일 이름만으로는 어떤 영상인지 구분이 어려움 | ⏳ |
| 6 | 음량 자동 맞춤 (유튜브/릴스 권장 음량) | 노래·원본 소리 크기가 들쭉날쭉 | ⏳ |
| 7 | 영상 시작/끝 페이드 인·아웃 | 갑자기 시작·끝나는 느낌 완화 | ⏳ |
| 8 | 비트 컷 전환 효과 (짧은 플래시/줌 등) | 비트 맞춤 영상의 완성도 | ⏳ |
| 9 | 제목 텍스트 넣기 | 자막과 별개로 큰 제목이 필요한 경우 | ⏳ |

## 기록

### 2026-10-28

**자율 테스트 (엣지 케이스 렌더링)** — 모두 통과
- 한글·공백·작은따옴표·쉼표·대괄호가 들어간 폴더/파일 이름 (입력, 음악, 출력 경로 모두)
- 10비트 HEVC 60fps, VP9(webm), 홀수 해상도(1081×1921, yuv444p), 모노 22kHz 오디오, 3000×4000 사진
- 회전 메타데이터가 있는 세로 폰 영상 → 똑바로 세워져서 화면을 채움
- 자막에 따옴표·쉼표·콜론·역슬래시·중괄호
- 5가지 조합(이어붙이기/세로 흐린배경+번갈아/정사각 잘라채우기+무작위/4:5+몰아서+자막+PiP/이어서+소프트자막)에서 해상도·길이 정확

**[1순위] 렌더링 병렬화**
- 1단계(조각 규격화)를 스레드 풀로 동시에 실행. 기본 동시 개수 = CPU 코어 절반(최대 4)
- 하나라도 실패하거나 취소하면 나머지 ffmpeg도 모두 중단
- 취소 테스트 추가: 병렬 렌더 중 취소하면 모든 ffmpeg가 멈추고 결과 파일이 남지 않음
- 측정 (4코어, 30초·1080×1920·컷 36개): 순차 45.7초 → 2개 동시 22.0초 → 4개 동시 20.5초

### 2026-10-13

- 첫 버전: 이어붙이기, 자동 자막(Whisper), 비트 맞춤 컷, 화면 속 화면, 내보내기
- 유튜브 링크 → mp3 받기, 음악 시작 위치 파형 게이지
- 자막 글꼴 파일 불러오기, 색·굵게·상자·위치
- 화면 비율(16:9 / 9:16 / 1:1 / 4:5)과 흐린 배경 채우기
- 비트 맞춤 장면 전환 버그 수정 → 컷마다 다음 파일로 넘어가도록 (번갈아/몰아서/무작위/이어서)
- 소리 출력 장치 선택 (헤드폰 자동 전환)
- 사용자 제보 "노래가 늘어짐": 렌더 결과물은 원곡과 0초 오차로 확인 → 앱 재생기 출력 장치 문제로 추정, 확인 대기
